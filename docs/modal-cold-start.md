# ลดเวลาเปิดเครื่อง (cold start) ของ Modal

## สถานะตอนนี้ (`modal_app.py`)
- **แคชโมเดล:** อยู่ใน Volume `dubbing-models` ประกอบด้วย `HF_HOME`, `TORCH_HOME` และ `PYTHAINLP_DATA_DIR` โหลดจากอินเทอร์เน็ตครั้งแรกครั้งเดียว
- **import torch:** ทำตอนเปิด container ผ่าน `image.imports()` ก่อนรับงาน
- **โหลดโมเดลขึ้นการ์ดจอ:** โหลดตอนใช้ครั้งแรกในแต่ละขั้น แล้วค้างไว้ใน container
- **ปิด container:** ปิดเมื่อว่างเกิน 60 วินาที (`scaledown_window=60`)
- **ฟังก์ชันบน Modal:** มี 3 ตัว แต่ละตัวเปิด container ของตัวเอง

| ฟังก์ชัน | โมเดลที่ใช้ |
|---|---|
| `analyze_audio` | BS-RoFormer หรือ Demucs, pyannote, faster-whisper |
| `resplit_turns` | pyannote หรือตัววัดลายเสียง |
| `synthesize_lines` | F5-TTS และ faster-whisper (ตรวจเสียงที่พากย์) |

## เวลาเปิดเครื่องหมดไปกับอะไร
1. **เปิดเครื่องที่มีการ์ดจอและโหลด image**
2. **`import torch` และไลบรารี ML:** ใช้เวลาหลายวินาที
3. **อ่านไฟล์โมเดลจาก Volume แล้วโหลดขึ้นการ์ดจอ:** ช้าที่สุด และต้องทำใหม่ทุกครั้งที่เปิด container

## ทางเลือก

### ก. ย้ายโมเดลไปเก็บใน image แทน Volume (ไม่แนะนำ)
- **ได้:** อาจเร็วขึ้นเล็กน้อยตอนอ่านไฟล์
- **เสีย:**
  - image ใหญ่ขึ้นหลายสิบ GB
  - อัปเดตแพ็กเกจหรือเปลี่ยนรุ่นโมเดลต้องสร้าง image ใหม่และโหลดโมเดลใหม่ทั้งหมด
  - ขั้นที่ 3 ยังต้องทำอยู่ดี

### ข. ยืด `scaledown_window` เป็น 3–5 นาที (ทำก่อน)
- **ได้:** งานที่ตามมาติดกัน เช่นแก้บทแล้วพากย์ใหม่ ใช้ container เดิมได้ ไม่ต้องรอเปิดเครื่อง
- **เสีย:** จ่ายค่าการ์ดจอช่วงที่ container ว่างรองานเพิ่มสูงสุด 3–5 นาทีต่อครั้ง
- **งาน:** แก้บรรทัดเดียว

### ค. Memory snapshot (ทำถ้าวัดแล้วเปิดเครื่องเกิน 30 วินาที)
- **วิธี:** เปลี่ยนฟังก์ชันเป็น `modal.Cls` แล้วให้ Modal เก็บสถานะในหน่วยความจำไว้ ครั้งต่อไปเปิดจาก snapshot ได้เลย
  - `@modal.enter(snap=True)`: import ไลบรารีและโหลดโมเดลไว้บน CPU
  - `@modal.enter(snap=False)`: ย้ายโมเดลขึ้นการ์ดจอหลังเปิดเครื่อง
- **ได้:**
  - ไม่ต้องรอขั้นที่ 2
  - ขั้นที่ 3 เหลือแค่ย้ายโมเดลขึ้นการ์ดจอ ไม่กี่วินาทีต่อโมเดล
- **ข้อจำกัด:**
  - ระหว่างทำ snapshot ใช้การ์ดจอไม่ได้ แบบที่เก็บสถานะการ์ดจอด้วยยังเป็นรุ่นทดลองของ Modal
  - snapshot ถูกล้างทุกครั้งที่ deploy: ครั้งแรกหลัง deploy ช้าเท่าเดิม
  - ต้องแก้ `gpu.py` จากโหลดโมเดลตอนใช้ครั้งแรก เป็นโหลดล่วงหน้าแยกตามฟังก์ชัน
  - ต้องทดสอบบน Modal จริง จึงมีค่าการ์ดจอระหว่างทดสอบ
- **เหมาะกับ:** งานสั้นที่ประมวลผลไม่ถึงนาที เช่น พากย์ใหม่บางประโยค เตรียมเสียงเข้าคลัง เตรียมเสียงอารมณ์ของนักพากย์
- **ช่วยน้อยกับ:** คลิปยาว 10–20 นาที

### ง. เปิด container ค้างไว้ (`min_containers=1`)
- **ได้:** ไม่ต้องรอเปิดเครื่องเลย
- **เสีย:** จ่ายค่าการ์ดจอตลอดเวลาที่เปิดไว้
- **เหมาะกับ:** ช่วงที่มีลูกค้าใช้มาก (ตั้งตามช่วงเวลาได้)

## ลำดับที่แนะนำ
1. **ทำข้อ ข:** ยืด `scaledown_window` เป็น 3–5 นาที
2. **วัดเวลาจาก log ของ Modal:** แยกเวลาเปิด container, import และโหลดโมเดลแต่ละตัว ของทั้ง 3 ฟังก์ชัน
3. **ตัดสินใจจากผลวัด:**
   - เปิดเครื่องเกิน 30 วินาที: ทำข้อ ค
   - เปิดเครื่อง 10–15 วินาที: ไม่คุ้มที่จะแก้โครงสร้างโค้ด
4. **ใช้ข้อ ง:** เมื่อมีลูกค้าประจำมากพอ

## ทุกข้อต้อง deploy Modal
แก้โค้ดได้ก่อน แต่การ deploy (`modal deploy modal_app.py`) ต้องรอคำสั่ง "deploy เลย"
