# ส่วน ก. คู่มือผู้ใช้

สำหรับผู้ใช้หน้าเว็บ: อัปโหลดคลิป ตรวจบท พากย์ และดาวน์โหลดผลลัพธ์


### ก.1 Pakdee คืออะไร

Pakdee แปลงคลิปภาษาต่างประเทศเป็นคลิปพากย์ไทยหรืออังกฤษ โดยระบบจะ

1. แยกเสียงพูดออกจากเพลง  
2. แยกว่าใครพูดตอนไหน  
3. ถอดเสียงแล้วแปลบทให้พอดีเวลาในฉาก  
4. พากย์ด้วยเสียงโคลนจากต้นฉบับ หรือเสียงจากคลัง  
5. รวมวิดีโอ พร้อมไฟล์ซับและเลเยอร์เสียงแยก  

เหมาะกับคลิปละคร อนิเมะ สัมภาษณ์ รีวิวสินค้า ฯลฯ

---

### ก.2 เริ่มต้นใช้งาน

#### 2.1 สมัคร / เข้าสู่ระบบ

1. เปิดหน้าเว็บ Pakdee  
2. กดสมัครหรือเข้าสู่ระบบ (เช่น Google)  
3. กรอกข้อมูลเบื้องต้น (ชื่อ เบอร์ ประเภทผู้ใช้) และยอมรับข้อกำหนด  

#### 2.2 แพ็กทดลอง (ให้อัตโนมัติ)

เข้าสู่ระบบด้วย Google แล้วระบบ**เปิดแพ็กทดลองให้อัตโนมัติ** ครั้งเดียวต่อบัญชี Google (ไม่ต้องกดรับเอง)  
ปิดบัญชีแล้วสมัครอีเมลเดิมอีกครั้ง หรือเปลี่ยนอีเมลใน Google บัญชีเดิม ก็ไม่ได้แพ็กทดลองซ้ำ  
ถ้าเคยรับไปแล้วหรือเป็นบัญชีผู้ดูแล จะไม่ให้อีก  
บัญชีที่มีแพ็กเสียเงินที่ยังไม่หมดอายุจะไม่ถูกทับ — เครดิตและสิทธิ์เดิมอยู่ครบ เมื่อแพ็กนั้นหมดอายุ ถ้ายังไม่เคยรับทดลอง จะได้ตอนเข้าสู่ระบบครั้งถัดไป

| รายการ | ค่า |
|---|---|
| เครดิตฟรี | 2 เครดิต |
| อายุ | 30 วัน |
| ความยาวคลิปสูงสุด | 2 นาที |
| ลายน้ำ | มีบนวิดีโอผลลัพธ์ |

#### 2.3 เครดิตคิดอย่างไร

- **1 เครดิต = คลิป 1 นาที** ตามความยาวจริง (เช่น 1:15 นาที = 1.25 เครดิต)  
- ตัดเครดิตงานใหม่ตอน**เริ่มวิเคราะห์** ตามความยาวคลิป (หรือช่วงที่ตัดก่อนพากย์)  
- **พากย์ซ้ำหลังงานเสร็จ:** 0.1 เครดิตต่อวินาทีของประโยคที่แก้  
  - ฟรีได้ไม่เกิน **10% ของความยาวคลิป**  
  - ประโยคที่ AI ติดธง (ถอดไม่ชัด / ควรตรวจ) **ฟรีเสมอ**  
- วิเคราะห์ไม่สำเร็จ → ได้เครดิตคืน  
- ใช้เครดิตแพ็กเกจก่อน แล้วค่อยใช้เครดิตเติม  

ซื้อแพ็กหรือเติมเครดิตได้ที่หน้าบัญชี / โปรโมชัน

---

### ก.3 ส่งคลิปพากย์

หน้าแรก `/` หรือปุ่ม **ส่งคลิปใหม่**

#### 3.1 เลือกแหล่งคลิป

- **อัปโหลดไฟล์** — `.mp4` `.mov` `.mkv` `.webm` `.avi` `.m4v`  
- **วางลิงก์** — YouTube, TikTok, Facebook, Bilibili ฯลฯ  

#### 3.2 ตั้งค่าก่อนส่ง

| ช่อง | คำอธิบาย |
|---|---|
| ภาษาต้นฉบับ | ว่าง = ให้ระบบตรวจเอง หรือระบุถ้ามั่นใจ |
| ภาษาพากย์ | ไทย หรือ อังกฤษ |
| จำนวนตัวละคร | ถ้ารู้ ให้ใส่ — แยกผู้พูดแม่นขึ้น |
| แนวเรื่อง | เช่น การ์ตูนเด็ก ละครจีน — ช่วยการแปล |
| คำศัพท์เฉพาะ | บรรทัดละคำ เช่น `ドラえもん = โดราเอมอน` |
| ตรวจบทก่อนพากย์ | แนะนำเปิดไว้ สำหรับงานจริง |
| ฝังซับ | ฝังซับลงวิดีโอผลลัพธ์ (ปรับรูปแบบได้ทีหลัง) |
| โปรเจกต์ | ถ้ามีโปรเจกต์ซีรีส์ ให้เลือก เพื่อจำตัวละครข้ามตอน |

กดส่งแล้วรอระบบวิเคราะห์ (แยกเสียง → ถอดเสียง → แปล)

---

### ก.4 ตามงานและความคืบหน้า

หน้า **งานทั้งหมด** `/jobs`

- กรองตามสถานะ: กำลังทำ / รอตรวจบท / เสร็จ / ล้มเหลว  
- ระหว่างทำงาน: เปิดงานนั้นเพื่อดูขั้นและความคืบหน้า  
- **ยกเลิก** ได้ระหว่างคิวหรือกำลังรัน  
- **ลองใหม่** ได้เมื่องานล้มเหลวหรือถูกยกเลิก  
- **ลบ** งานและไฟล์ทั้งหมด (กู้คืนไม่ได้)

| สถานะ | ความหมาย | ขั้นถัดไป |
|---|---|---|
| กำลังประมวลผล | วิเคราะห์หรือพากย์อยู่ | รอ หรือยกเลิก |
| รอตรวจบท | แปลเสร็จ รอคุณแก้บท | แก้บท แล้วกดพากย์ |
| เสร็จ | มีวิดีโอพากย์แล้ว | ดาวน์โหลด / แก้บทพากย์ใหม่ |
| ล้มเหลว | มีข้อผิดพลาด | ลองใหม่ หรือส่งคลิปใหม่ |

---

### ก.5 ตรวจบทก่อนพากย์ (สำคัญ)

เมื่อสถานะเป็น **รอตรวจบท** หน้างานจะแสดงวิดีโอต้นฉบับคู่กับบทแปล

#### สิ่งที่ควรทำ

1. เล่นคลิป ดูซับและรายการประโยคทางขวา  
2. แก้คำแปลให้สั้น พอดีปาก และถูกบริบท  
3. เปลี่ยนตัวละครของประโยคถ้าระบบจัดคนผิด  
4. ตั้งชื่อตัวละคร (เช่น โนบิตะ) เพื่อให้อ่านง่าย  
5. เลือกเสียงจากคลังให้ตัวละคร (ถ้าต้องการ) หรือใช้เสียงโคลนจากต้นฉบับ  
6. กด **บันทึกและเริ่มพากย์**

ระบบจะบันทึกการแก้ทั้งหมดก่อน แล้วเข้าคิวพากย์

#### เคล็ดลับตรวจบท

- ใส่ชื่อเฉพาะในช่องคำศัพท์ตั้งแต่ตอนส่งคลิป  
- ท่อนสั้นมาก / เพลงจบตอน / เสียงเอฟเฟกต์ — ลบหรือรวมกับท่อนข้าง ๆ  
- บทยาวเกินช่องปาก → ย่อเอง หรือให้ระบบย่อตอนแปล  
- ถ้ามีหลายคนพูด ตรวจว่าสี/ชื่อตัวละครสลับถูกต้อง  

---

### ก.6 ผลลัพธ์และดาวน์โหลด

เมื่องาน **เสร็จ** จะดาวน์โหลดได้ประมาณนี้

| ไฟล์ | เนื้อหา |
|---|---|
| วิดีโอพากย์ | MP4 เสียงพากย์ + เพลงเดิม |
| ซับ `.srt` | ไฟล์ซับแยก |
| ZIP | วิดีโอ + ซับ รวมกัน |
| เลเยอร์เสียง | เสียงแต่ละตัวละคร, เพลง, เสียงพากย์ล้วน, เสียงผสม |

ปรับรูปแบบซับ (ฟอนต์ สี ขนาด ตำแหน่ง) แล้วฝังซับใหม่ได้โดยไม่ต้องพากย์ซ้ำ

#### แก้หลังพากย์แล้ว

1. เปิดงานที่เสร็จแล้ว  
2. เข้าโหมดแก้บท  
3. แก้เฉพาะประโยคที่ต้องการ  
4. กด **บันทึกและพากย์ใหม่**  

ระบบพากย์เฉพาะประโยคที่เปลี่ยน — เครดิตพากย์ซ้ำคิดเฉพาะช่วงที่แก้ (โควตาฟรี 10% + บรรทัดที่ AI ติดธง)

### ก.7 คลังเสียง

หน้า `/voices`

- เลือกเสียงพากย์ไทยที่มีในระบบมาผูกกับตัวละครในงาน  
- บางเสียงมีหลายอารมณ์ (โกรธ เศร้า สุข ฯลฯ)  
- แพ็กทดลองใช้ได้เฉพาะเสียงมาตรฐานที่แอดมินเปิดไว้  

ถ้าต้องการส่งเสียงตัวเองเข้าระบบ ใช้หน้าสมัครนักพากย์ (`/actor`) — ผู้ดูแลอนุมัติก่อนถึงจะขึ้นคลัง

### ก.8 โปรเจกต์ (หลายตอน)

หน้า `/projects`

ใช้เมื่อพากย์ซีรีส์หลายตอนที่ตัวละครชุดเดิม

1. สร้างโปรเจกต์ ตั้งภาษาพากย์  
2. ส่งคลิปโดยเลือกโปรเจกต์นั้น  
3. ระบบช่วยจับคู่ตัวละครข้ามตอนจากลายเสียง  
4. ตั้งชื่อและเสียงพากย์ประจำตัวละครในโปรเจกต์

### ก.9 การตั้งค่า

ค่าเหล่านี้ใช้กับงานใหม่ ไม่ย้อนแก้งานเก่าอัตโนมัติ

### ก.11 คำถามที่พบบ่อย

**พากย์แล้วเสียงไม่ตรงบท**  
แก้บทนั้นให้ชัดขึ้น แล้วพากย์ใหม่เฉพาะท่อน หรือฟังต้นฉบับแล้วเขียนใหม่สั้นลง

**ตัวละครสลับคน**  
ตอนตรวจบท เปลี่ยนป้ายผู้พูดทีละประโยค แล้วพากย์ใหม่

**เครดิตไม่พอ**  
ได้แพ็กทดลองอัตโนมัติตอนเข้าสู่ระบบ (ถ้ายังไม่มีแพ็กที่ใช้งานอยู่) หรือซื้อแพ็ก/เติมเครดิต

**ลิงก์ดาวน์โหลดไม่ได้**  
ลองอัปโหลดไฟล์แทน หรือตรวจว่าลิงก์สาธารณะดูได้โดยไม่ล็อกอิน

**งานล้มเหลว**  
กดลองใหม่ ถ้าซ้ำ ให้ส่งคลิปสั้นลง หรือระบุภาษาต้นฉบับ

**มีลายน้ำ**  
แพ็กทดลองมีลายน้ำ — ซื้อแพ็กเสียเงินเพื่อเอาลายน้ำออก

### ข.1 โปรแกรมนี้ทำอะไร

Pakdee พากย์คลิปต่างประเทศเป็นภาษาไทยหรืออังกฤษ โดยใช้เสียงโคลนจากนักแสดงต้นฉบับหรือเสียงจากคลังเสียงไทย

**ที่ผู้ใช้ทำได้**
- ส่งไฟล์วิดีโอ ลิงก์ (YouTube, TikTok, Facebook, Bilibili) หรือไทม์ไลน์จากโปรแกรมตัดต่อ (FCP XML, FCPXML, EDL, OTIO)
- ตรวจและแก้บทก่อนพากย์ เลือกเสียงต่อตัวละคร แล้วดาวน์โหลดวิดีโอ ซับ และเสียงแยกเลเยอร์
- รวมหลายตอนของเรื่องเดียวกันเป็นโปรเจกต์ ให้ระบบจำตัวละคร คำเฉพาะ และคำแปลที่เคยแก้

**หลักการของระบบ**
- ผู้ใช้ควบคุมได้ก่อนพากย์ ระบบหยุดรอที่หน้าตรวจบท (ถ้าเปิดไว้) การแก้บทหลังพากย์พากย์ใหม่เฉพาะประโยคที่เปลี่ยน
- ขั้นที่ใช้การ์ดจอรันบน Modal ส่วนขั้น CPU และการแปลรันบนเครื่อง API
- ข้อมูลทั้งหมดอยู่ใน Postgres (ไม่ใช้ SQLite หรือไฟล์ JSON เป็นที่เก็บหลัก) ไฟล์เสียงและวิดีโออยู่ในดิสก์ของ API และ R2

### ข.5 ระบบแปล (translate.py)

ไฟล์: [backend/app/pipeline/translate.py](../backend/app/pipeline/translate.py) เรียกโมเดลผ่านฟังก์ชัน `_chat()` ทุกขั้นใช้โมเดลตัวเดียวกัน ถ้าตั้ง `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` จะใช้โมเดลนั้น (production ใช้ Qwen3-30B-A3B บน Modal แอป `pakdee-llm` ชื่อโมเดล `qwen`) ถ้าไม่ตั้งใช้ `TYPHOON_*` เดิม (OCR สลิปใช้ Typhoon เสมอ)

#### 5.1 วิเคราะห์เรื่องก่อนแปล (`story`)

อ่านบททั้งเรื่องแล้วได้: สรุปเรื่อง แนวเรื่อง ตัวละคร (ชื่อ บทบาท สรรพนาม) คำเฉพาะ และประโยคที่ผู้พูดน่าจะผิด
ถ้าเปิด `STORY_CONTENT_TYPE` จะได้ `content_type` ด้วย:

| ชนิด | ความหมาย | ผลต่อการแปล |
| --- | --- | --- |
| เรื่องต่อเนื่อง | ฉากเรียงกันเป็นเรื่องเดียว | ตรวจความต่อเนื่องของประโยคหลังแปล แปลใหม่ได้ |
| ทีเซอร์/รวมฉาก | ตัดต่อสั้น ๆ จากหลายฉาก | ตรวจแค่ชื่อและศัพท์ให้ตรงกัน ติดป้ายอย่างเดียว |

#### 5.2 แปลเป็นชุด

- ประโยคถูกจัดกลุ่ม (`_group_lines`) ที่ห่างกันไม่เกิน 1.5 วินาที แล้วส่งครั้งละ 20 ประโยค (`TRANSLATE_BATCH_SIZE`)
- แต่ละชุดได้บริบท (เมื่อเปิด `TRANSLATE_NEIGHBORS`):
  - **3 ประโยคก่อนหน้า** (ต้นฉบับและคำแปลที่ได้แล้ว) ติดป้าย "บริบท ห้ามแปล"
  - **2 ประโยคถัดไป** (เฉพาะต้นฉบับ) ติดป้ายเดียวกัน
  - โมเดลต้องแปลเฉพาะประโยคในชุด รูปแบบคำตอบเหมือนเดิม
- ใส่ผลของ `story` (ตัวละคร ศัพท์) และความจำคำแปลของโปรเจกต์ (คู่ต้นฉบับ → บทที่ผู้ใช้เคยแก้) เป็นตัวอย่าง

#### 5.3 ย่อและขยายบท (`fit_lengths`)

คำนวณเวลาพูดจากอัตราตัวอักษร/พยางค์/คำต่อวินาที (`THAI_CHARS_PER_SEC`, `THAI_SYLLABLES_PER_SEC`, `EN_WORDS_PER_SEC`)
ประโยคที่ยาวเกินถูกย่อ (`shorten`) ที่สั้นเกินถูกขยาย (`lengthen`) โดยส่งประโยคข้างเคียงให้ (เมื่อเปิด `FIT_NEIGHBORS`)
เพื่อคงความหมายที่เชื่อมกัน ใส่เครื่องหมาย `/` ตรงที่ต้นฉบับหยุด เพื่อให้ TTS หยุดตรงจังหวะ

#### 5.4 ความจำคำแปล

เมื่อผู้ใช้แก้บทแล้วพากย์ ระบบเก็บคู่ต้นฉบับ → บทที่แก้ไว้ในโปรเจกต์ ตอนต่อไปส่งเป็นตัวอย่างตอนแปล
ดู/ลบได้ที่ `/projects/{id}/memory`

#### 5.5 ตรวจหลังแปล (`review_translation`)

รันหลัง `fit_lengths` ถ้าเปิด `TRANSLATE_REVIEW` และมีคีย์ API (ไม่รันในโหมด mock) ความล้มเหลวของขั้นนี้บันทึก log เท่านั้น ไม่ทำให้งานล้ม

| ชนิดคลิป | ทำอะไร |
| --- | --- |
| เรื่องต่อเนื่อง | หาประโยคที่ความหมายไม่ต่อกัน แปลใหม่ได้ไม่เกิน `REVIEW_ROUNDS` (2) รอบ แล้วตรวจซ้ำ ประโยคที่ยังไม่ผ่านติดป้าย |
| ทีเซอร์ | ตรวจชื่อและศัพท์ให้ตรงกับคำเฉพาะของเรื่อง ติดป้าย "ควรตรวจ" อย่างเดียว ไม่แปลใหม่ |

เหตุผลติดป้ายเก็บใน `Utterance.check_note` แสดงที่หน้าตรวจบทเป็นป้าย "ควรตรวจ" และถูกล้างเมื่อผู้ใช้แก้ข้อความหรือแปลใหม่

> **ข้อควรระวัง:** ขั้นนี้เรียกโมเดลเพิ่ม (เสียค่า API เพิ่ม) และตอนนี้ถ้าแปลใหม่แล้วไม่ผ่านการตรวจซ้ำ ระบบยังไม่ย้อนกลับไปใช้คำแปลเดิม

#### 5.6 กฎการแปลและบทภาษาพูด

`SYSTEM_PROMPT_TH` ใช้ได้กับคลิปเสียงทุกประเภท (ไม่ผูกกับตัวอย่างคลิปใดคลิปหนึ่ง) กฎหลัก: แต่ละท่อนแปลจากข้อความของท่อนนั้นเท่านั้น ห้ามนำความจากบรรทัดข้างเคียงมาปน ยึดความหมายก่อนสำนวน คงระดับอารมณ์และความสุภาพเท่าต้นฉบับ ใช้คำเรียกสิ่งเดียวกันให้ตรงกันทั้งเรื่อง ไม่ใส่คำเน้นซ้อนกัน และไม่เปลี่ยนวิธีที่ผู้พูดเรียกผู้ฟัง
ชื่อแบรนด์เขียนทับศัพท์ตามเสียง เช่น Siri → ซิริ, Alexa → อเล็กซา, TikTok → ติ๊กต็อก, ChatGPT → แชตจีพีที

#### 5.7 ปรับเป็นภาษาพูด (`naturalize_dialogue`)

รันหลัง `fit_lengths` เมื่อเปิด `AI_NATURALIZE` (ค่าเริ่ม เปิด) ให้โมเดลอ่านบทพร้อมต้นฉบับและบริบท (ก่อนหน้า 3 บรรทัด ถัดไป 2 บรรทัด) แก้บรรทัดที่ฟังเป็นภาษาเขียนหรือแปลตรงตัว
กติกา: ตรวจความหมายเทียบต้นฉบับก่อน แก้คำลงท้ายที่ค้าง ความยาวเพิ่มได้ไม่เกิน 20% และคืนบรรทัดเดิมถ้าดีอยู่แล้ว

#### 5.8 ตรวจความถูกต้องของคำแปล (`verify_translation`)

รันหลัง `naturalize` เมื่อเปิด `TRANSLATE_VERIFY` (ค่าเริ่ม เปิด) และมีคีย์โมเดล (ไม่รันในโหมด mock) โมเดลตรวจทีละ 8 บรรทัดว่าบทพากย์ตรงความหมายต้นฉบับหรือไม่ (เติมความที่ไม่มี ตกความ เนื้อหาเพี้ยน) แล้วคืนรายการบรรทัดที่เพี้ยนพร้อมเหตุผล
- จำนวนบรรทัดที่ติดป้ายไม่เกิน 40% ของงาน
- ค่าเริ่มต้น **ติดป้ายอย่างเดียว** ไม่แก้บท เหตุผลลงใน `check_note` และ `unclear_reason` ผู้ใช้เห็นเป็นป้าย "ควรตรวจ"
- ถ้าเปิด `TRANSLATE_VERIFY_FIX` ระบบแปลบรรทัดที่เพี้ยนใหม่ได้ไม่เกิน `VERIFY_ROUNDS` (2) รอบ แล้วตรวจซ้ำ บรรทัดที่ยังเพี้ยนหรือยาวขึ้นเกิน 1.35 เท่าจะถูกคืนเป็นบทเดิม (เหตุที่ปิดไว้: การแก้อัตโนมัติเคยแต่งเนื้อหาเพิ่ม)
- ความล้มเหลวของขั้นนี้บันทึก log เท่านั้น ไม่ทำให้งานล้ม ทดสอบด้วย [backend/tests/test_verify_translation.py](../backend/tests/test_verify_translation.py)

#### 5.9 ค่าตั้งของการแปล

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `STORY_CONTENT_TYPE` | เปิด | ให้ story ระบุชนิดคลิป |
| `TRANSLATE_NEIGHBORS` | เปิด | ส่งบริบท 3 ก่อนหน้า 2 ถัดไปตอนแปล |
| `FIT_NEIGHBORS` | เปิด | ส่งประโยคข้างเคียงตอนย่อ/ขยาย |
| `TRANSLATE_REVIEW` | ปิด | ขั้นตรวจหลังแปล (เปิดโดยแก้ `defaults.py`) |
| `AI_NATURALIZE` | เปิด | ปรับบทเป็นภาษาพูด (ข.5.7) |
| `TRANSLATE_VERIFY` | เปิด | ตรวจความถูกต้องของคำแปล (ข.5.8) |
| `TRANSLATE_VERIFY_FIX` | ปิด | ให้ขั้นตรวจแปลบรรทัดที่เพี้ยนใหม่เอง (ค่าเริ่มติดป้ายอย่างเดียว) |
| `TRANSLATE_BATCH_SIZE` | 20 | จำนวนประโยคต่อชุด |

ค่าคงที่ในโค้ด: `CONTEXT_BEFORE=3`, `CONTEXT_AFTER=2`, `REVIEW_ROUNDS=2`, `TERMS_BATCH_SIZE=60`
ทดสอบด้วย [backend/tests/test_translate_context.py](../backend/tests/test_translate_context.py)

### ข.6 ผู้พูด เสียง และอารมณ์

#### 6.1 ผู้พูด

- แยกผู้พูดด้วย pyannote แล้วปรับด้วยลายเสียง (`DIAR_REFINE`, `DIAR_EXCLUSIVE`, `DIAR_MERGE_SIM`)
- กู้ประโยคที่พูดซ้อนกัน (`OVERLAP_RECOVER`) และตัดท่อนที่สองคนพูดต่อกัน (`TURN_SPLIT`)
- ในโปรเจกต์ ตอนใหม่จับคู่ผู้พูดกับตัวละครด้วยลายเสียงเอง เฉพาะที่มั่นใจ (`VOICE_MATCH`, `VOICE_MIN_SIM`)

#### 6.2 เลือกเสียงพากย์

- ต่อตัวละคร เลือก **เสียงต้นฉบับ** (โคลนจากคลิป) หรือ **เสียงจากคลัง**
- เสียงต้นฉบับเลือกท่อน 3–10 วินาทีที่สะอาดที่สุดเป็นตัวอย่าง (`REF_MIN_SEC`, `REF_MAX_SEC`, `REF_MIN_QUALITY`)

#### 6.3 คลังเสียง ([voice_library.py](../backend/app/voice_library.py))

อัปโหลดเสียงไทย ระบบแยกเพลง ถอดข้อความ คัดท่อนที่ดี เสียงหนึ่งมีได้หลายอารมณ์ (`moods/<mood>/`)
**เมนูเลือกอารมณ์และการเลือกอารมณ์อัตโนมัติจะแสดงเมื่อเสียงนั้นมีตัวอย่างมากกว่าหนึ่งอารมณ์เท่านั้น**
ถ้าเลือกเสียงต้นฉบับหรือเสียงที่มีอารมณ์เดียว ผู้ใช้จะไม่เห็นตัวเลือกนี้ และหน้าตรวจบทไม่แสดงอารมณ์ของต้นฉบับ

#### 6.4 ปรับให้ใกล้ต้นฉบับ

จังหวะหยุด (`PAUSE_MATCH`), ความตื่นเต้น (`EMOTION_MATCH`), ความดัง (`LOUDNESS_MATCH`), การขึ้นลงเสียง (`PROSODY_MATCH`), เสียงก้องห้อง (`ROOM_REVERB`), เสียงหายใจ (`BREATH_KEEP`)

### ข.7 ข้อมูลและฐานข้อมูล

หลักการ: **ข้อมูลทั้งหมดต้องอยู่ใน Postgres** ไม่ใช้ SQLite หรือไฟล์ JSON เป็นที่เก็บหลัก (ไฟล์ JSON/`accounts.db` ที่เหลือเป็นสำรองหรือโหมดพัฒนา)

| ข้อมูล | ที่เก็บ |
| --- | --- |
| ผู้ใช้ session เครดิต นักพากย์ ค่าตอบแทน | schema `studio` ผ่าน `pgstore` |
| งาน บท โปรเจกต์ | `studio.jobs`, `transcripts`, `projects` |
| คลังเสียง ค่าตั้ง ความจำคำแปล คุณภาพ metrics | ผ่าน `supabase_db` |
| ไฟล์เสียงและวิดีโอ | `data/` บน PVC ของ API และ R2 สำหรับงานเก่า |
| สำรองข้อมูล | `/app/backups` ทุก `BACKUP_HOURS` ชั่วโมง เก็บ `BACKUP_KEEP` ชุด |

Postgres รันเป็น StatefulSet ใน k3s (`db:5432` ภายในคลัสเตอร์เท่านั้น) SQL เริ่มต้นอยู่ใน `deploy/db/init/`
ฐานข้อมูลที่มีอยู่แล้วไม่รัน init ซ้ำ การเพิ่มคอลัมน์ต้องใช้ไฟล์ใน `backend/supabase/migrations/` รันมือหลังสำรองข้อมูล

### ข.8 บัญชี เครดิต นักพากย์ และกฎหมาย

#### บัญชี
- ล็อกอินด้วย Google (`AUTH_ENABLED`) ผู้ใช้เห็นเฉพาะงานของตัวเอง ผู้ดูแลกำหนดด้วย `ADMIN_EMAILS`
- ระบบให้แพ็กทดลองอัตโนมัติเมื่อเข้าสู่ระบบด้วย Google ครั้งเดียวต่อตัวตน Google (`POST /billing/trial` ก็เรียกได้) รายละเอียดสำหรับผู้ใช้อยู่ในส่วน ก. หัวข้อ ก.2 (2.2)
- ดาวน์โหลดข้อมูลของตัวเอง (`/auth/export`) และปิดบัญชี (`/auth/close`)

#### เครดิตและแพ็กเกจ (`BILLING_ENABLED`)
- 1 เครดิตต่อคลิป 1 นาที ผู้ดูแลไม่ถูกตัดเครดิต
- เติมเงินผ่านสลิป (ผู้ดูแลอนุมัติ) หรือ Stripe (`/billing/webhooks/stripe`) มีใบเสนอราคาก่อนส่งงาน (`/billing/quote`) และสำหรับพากย์ใหม่ (`/billing/quote-redub`)

#### นักพากย์ ([actors.py](../backend/app/actors.py))
สมัคร → ผู้ดูแลอนุมัติ → ยอมรับหนังสือยินยอม PDPA และสิทธิ์ใช้เสียง → อัดเสียงหลายอารมณ์ → ผู้ดูแลตรวจฟัง
ระบบบันทึกวินาทีที่เสียงถูกใช้ทุกงาน คิดค่าตอบแทนรายเดือน (`ACTOR_RATE_SATANG_PER_MIN`) หักภาษี ณ ที่จ่าย ส่งออก CSV

#### ความยินยอมและ PDPA
ข้อกำหนด นโยบายความเป็นส่วนตัว และการรับข่าวสารถูกบันทึกเป็นหลักฐาน (เวอร์ชัน แฮช เวลา IP) เปลี่ยนเวอร์ชันแล้วต้องยอมรับใหม่
ต้องตั้ง `PDPA_CONTROLLER_NAME` และ `PDPA_CONTROLLER_CONTACT` ก่อนเปิดให้ลูกค้าจริง

#### ผู้ดูแลระบบ (`/admin`)
ผู้ใช้ เครดิต แพ็กเกจ นักพากย์ ตรวจเสียง ค่าตอบแทน การชำระเงิน รายงานเสียง ข้อเสนอแนะ สำรองข้อมูล
และหน้า **คุณภาพ** ที่แสดงสัดส่วนบรรทัดที่ผู้ใช้แก้ (คำแปล ผู้พูด เวลา เพิ่ม ลบ) รายสัปดาห์และรายคู่ภาษา พร้อมดาวน์โหลดบรรทัดที่แก้เป็น CSV

### ข.9 การเข้ารหัสข้อมูลส่วนบุคคล (PII)

เลขประจำตัวผู้เสียภาษี (`tax_id`) และเลขบัญชี (`account_no`) ของนักพากย์ถูกเข้ารหัสในแอปก่อนลงฐานข้อมูล
รายละเอียดเต็มอยู่ใน [pii-encryption.md](pii-encryption.md) สรุปดังนี้

| เรื่อง | รายละเอียด |
| --- | --- |
| อัลกอริทึม | AES-256-GCM รูปแบบ `v<เวอร์ชัน>:` + base64(nonce 12 ไบต์ + ciphertext) ข้อมูลเพิ่มเติม (AAD) คือ `table:column:row_id` |
| ดัชนีค้นหา | `tax_id_hmac` = HMAC-SHA256 ของเลขหลังตัดเว้นวรรคและขีด รับเฉพาะเลข 0-9 ASCII |
| ตารางและคอลัมน์ | `studio.actor_payment`: `tax_id_enc`, `tax_id_hmac`, `account_no_enc` / `studio.actor_payouts`: `tax_id_enc`, `tax_id_hmac` |
| กุญแจ | จาก Secret `pakdee-pii`: `PII_ENC_KEYS`, `PII_ENC_ACTIVE_VERSION`, `PII_HMAC_KEY` ถ้าขาด API ไม่สตาร์ท |
| การอ่าน | อ่านจากคอลัมน์เข้ารหัสก่อน ถ้าถอดรหัสไม่ได้การอ่านล้ม ไม่ย้อนไปใช้ plaintext |
| คอลัมน์เดิม | `tax_id` และ `account_no` (plaintext) ยังอยู่ รอการเปลี่ยนรอบหน้า |

**สถานะ production (2026-11-16):** สร้าง Secret `pakdee-pii` แล้ว รัน migration แล้ว และ backfill 2 แถวใน `actor_payment` เสร็จ (เวอร์ชัน `v1`)
**กุญแจเดียวที่เข้ารหัสข้อมูลอยู่ในสองที่คือ Secret บนคลัสเตอร์ และไฟล์สำรอง** ถ้าหายทั้งคู่ ข้อมูลที่เข้ารหัสแล้วอ่านไม่ได้

ตารางนี้จัดกลุ่มเส้นทางหลัก (ไม่ใช่รายการครบทุกเส้นทาง รายการเต็มดูใน [main.py](../backend/app/main.py) และ [account_api.py](../backend/app/account_api.py))

### ข.13 การ deploy และ CI

#### 13.1 CI/CD
ไฟล์ [.github/workflows/deploy-k3s.yml](../.github/workflows/deploy-k3s.yml) ชื่อ **CI and deploy k3s**

| งาน | ทำอะไร |
| --- | --- |
| `pytest` | รัน pytest ใน `backend/` |
| `typecheck` | `npm run typecheck` (`tsc --noEmit`) ใน `frontend/` |
| `test` | ต้องให้ทั้งสองข้างสำเร็จ (success เท่านั้น ข้ามหรือยกเลิกถือว่าล้ม) เป็นชื่อเช็กที่ branch protection ของ `main` ใช้ |
| `build` | build ภาพ api และ web push ไป ghcr.io แท็กด้วย git SHA |
| `deploy` | SSH เข้าเครื่อง `kubectl apply` และรอ rollout |

push เข้า `main` จึงเริ่ม build และ deploy ถ้า `test` ผ่านเท่านั้น Kite (แดชบอร์ด) ติดตั้งแยกผ่าน Run workflow ที่ติ๊ก `install_kite`
workflow เก่า `deploy-vps.yml` (Compose) ไม่รันเอง ใช้เฉพาะตอนย้อนกลับตาม [ROLLBACK.md](../deploy/k8s/ROLLBACK.md)

#### 13.2 ก่อน deploy ครั้งแรกหรือหลังเพิ่มของใหม่
1. Secret ต้องมีครบ: `pakdee-secrets`, `ghcr-pull`, `pakdee-pii` ถ้าขาด pod ค้างที่ `CreateContainerConfigError` และ rollout ถูกย้อนกลับ
2. ถ้ามีการเพิ่มคอลัมน์ ให้สำรองฐานข้อมูลแล้วรัน SQL ใน `backend/supabase/migrations/` ก่อนปล่อยภาพที่เขียนคอลัมน์ใหม่
3. หลัง deploy ที่เพิ่มการเข้ารหัส ให้รัน `python -m app.pii_backfill --dry-run --count-only` แล้วรันจริง

#### 13.3 คำสั่งที่ใช้บ่อย

```bash
# สถานะ
kubectl -n pakdee get pods
kubectl -n pakdee rollout status deploy/api
kubectl -n pakdee logs deploy/api -c api --tail=100

# สำรองฐานข้อมูล
kubectl -n pakdee exec statefulset/db -- sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner' > backup.sql

# backfill PII
kubectl -n pakdee exec deployment/api -c api -- python -m app.pii_backfill --dry-run --count-only
kubectl -n pakdee exec deployment/api -c api -- python -m app.pii_backfill --batch 200 --count-only
```

#### 13.4 สิ่งที่ห้ามทำ
- ห้ามรัน `enable-ingress.sh` (ต้องตั้ง `CONFIRM_PUBLIC_TRAEFIK` ก่อน และจะแย่งพอร์ต 80/443 จาก Caddy)
- ห้ามตั้ง Service ของ Traefik เป็น LoadBalancer หรือ NodePort (กลายเป็น listener สาธารณะ)
- ห้ามเปิด Compose `api` และ `web` ซ้ำขณะที่ k3s ทำงาน
- ห้ามตั้ง `PII_ENC_DEV_EPHEMERAL=1` ในคลัสเตอร์

#### 13.5 การพัฒนาในเครื่อง
- `MOCK_PIPELINE=1` รันครบทุกขั้นโดยไม่โหลดโมเดล
- `pytest` ใน `backend/` และ `npx tsc --noEmit` ใน `frontend/` ก่อน push (ทั้งสองคือสิ่งที่ CI ตรวจ)
- เครื่องพัฒนาของเจ้าของ: ไดรฟ์ C เต็ม Docker และแคชโมเดลอยู่ไดรฟ์ E

### ข.15 ปัญหาที่รู้อยู่และงานค้าง

#### ปัญหาที่พบจากการตรวจงานจริง

1. **เสียงพากย์ว่าง (TTS เงียบ)** ประโยคสั้นมากบางประโยคได้ไฟล์เสียงที่เงียบสนิท (พบในงาน `965a76960efd` บรรทัด 14–16) **แก้แล้วและ merge เข้า main (รอทดสอบกับงานจริง)** ดูตาราง ข.4.2
   สาเหตุที่ยืนยัน: `_fit()` จำกัดความยาวที่ขอไว้ที่ความยาวธรรมชาติ ×1.05 (`MAX_SLOWDOWN`) พื้นต่ำสุดแค่ 0.3 วินาที และรอบลองใหม่ขอความยาวเดิม ค่าที่เพิ่มใหม่เป็นค่าตั้งต้นที่ต้องปรับจากงานจริง
2. **ประโยคถูกตัดกลางคัน** การแปลจัดกลุ่มที่ช่องว่าง 1.5 วินาที แต่การพากย์ที่ 0.6 วินาที ประโยคที่ยังพูดไม่จบอาจถูกแยก
   ทางแก้ที่เสนอ: ขยายการจัดกลุ่มสำหรับประโยคที่ยังไม่จบ
3. **การตรวจหลังแปลยังไม่ปลอดภัยพอ** ถ้าแปลใหม่แล้วไม่ผ่านการตรวจซ้ำ ควรย้อนกลับไปใช้คำแปลเดิม
4. **ค่าเปิด/ปิดบางตัวอ่านจาก `defaults.py` เท่านั้น ไม่อ่านจากตัวแปรสภาพแวดล้อม** เช่น `TRANSLATE_REVIEW` และ `RETRANSCRIBE_NOISY` (ตั้งเป็น 0 ใน `.env` หรือ ConfigMap ไม่มีผล) ต้องแก้ไฟล์แล้ว build ใหม่ ตอนนี้ปิดทั้งสองตัวแล้ว
5. **ขั้นขยายบท (`fit_lengths`) เติมเนื้อหาเอง** บรรทัดที่ต้นฉบับถูกตัดกลางประโยคอาจถูกขยายด้วยความที่ต้นฉบับไม่ได้พูด ตัวตรวจแปล (ข.5.8) จับได้บางส่วน ทางแก้ที่เสนอ: ไม่ขยายบรรทัดที่ต้นฉบับยังไม่จบประโยค และขยายด้วยการเปลี่ยนคำเท่านั้น
6. **แยกผู้พูดสลับในคลิปคนเดียว** ในคลิปที่มีคนพูดคนเดียว บางบรรทัดอาจถูกแยกเป็นอีกตัวละคร (พบในงาน `b4b303423012`) ทำให้ได้เสียงพากย์คนละเสียง แก้ได้ที่หน้าไทม์ไลน์ด้วยการรวมตัวละคร (ปุ่ม ✕)
7. **อารมณ์ของต้นฉบับไม่แสดงบนหน้าตรวจบท** และไม่มีข้อความอธิบายเมื่อเสียงที่เลือกไม่มีตัวอย่างอารมณ์

# ส่วน ค. ภาคผนวก

## ค.1 ตัวเลือกลดเวลาเปิดเครื่อง (cold start) ของ Modal

เวลาเปิดเครื่องหมดไปกับ: เปิดเครื่องและโหลด image → `import torch` → อ่านโมเดลจาก Volume แล้วโหลดขึ้นการ์ดจอ (ช้าสุด)

| ทางเลือก | ผล | ข้อเสีย | คำแนะนำ |
|---|---|---|---|
| เก็บโมเดลใน image แทน Volume | เร็วขึ้นเล็กน้อย | image ใหญ่หลายสิบ GB สร้าง image ใหม่ทุกครั้งที่อัปเดต | ไม่ทำ |
| ยืด `scaledown_window` เป็น 3–5 นาที | งานที่ตามมาติดกันไม่ต้องรอเปิดเครื่อง | จ่ายช่วงว่างเพิ่ม | ทำก่อน แก้บรรทัดเดียว |
| Memory snapshot (`modal.Cls` + `@modal.enter(snap=True)`) | ข้าม import และอ่านโมเดล เหลือแค่ย้ายขึ้นการ์ดจอ | ต้องแก้โครงสร้างโหลดโมเดลใน `gpu.py`, snapshot ล้างทุก deploy, แบบเก็บสถานะการ์ดจอยังทดลอง | ทำถ้าวัดแล้วเปิดเครื่องเกิน 30 วินาที |
| `min_containers=1` | ไม่ต้องรอเลย | จ่ายค่าการ์ดจอตลอดเวลา | เมื่อมีลูกค้ามากพอ |

ขั้นต่อไป: วัดเวลาจาก log ของ Modal แยกตามฟังก์ชันก่อนตัดสินใจ
